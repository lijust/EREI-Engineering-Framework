# Core13 — سياسة إغلاق النسخة الهندسية التجريبية | Pilot Closure Contract v1.0

**تاريخ التجميد:** 7 نوفمبر 2026. **الحالة:** PROPOSED / AWAITING_OWNER_REVIEW. **المرجع التنفيذي:** [EREI-3.2 #307](https://github.com/lijust/EREI-3.2/issues/307).

## 1. القرار وحدود المشروع

من الآن، **لا تُضاف مراحل F5B1L أو F5B1M أو توسعات أمنية تلقائيًا**. المسار الحالي ينتهي بثلاث حزم محددة سلفًا، بالترتيب **A → B → C**. لا تتوسع الحزمة عند ظهور نتيجة اختبار جديدة؛ تُسجل الثغرة مع أثرها، ثم إما تُصلح في حدود الحزمة خلال ميزانيتها، أو تُعتمد نتيجة **NO_GO / BLOCKED**. لا يُساوى بين إغلاق تقييم الحزمة وبين التصريح بالتشغيل.

**هدف النسخة الحالية** هو إصدار قرار قابل للمراجعة بشأن Pilot داخلي **استشاري وغير منفذ للأكواد**. الهدف ليس إنتاج حاوية عامة لتشغيل كود AI، ولا إثبات أمان Docker عالميًا، ولا منح اعتماد Stable.

**ما لا يتغير مهما كانت نتائج A/B/C:**  
- AI_ACCEPTANCE = BLOCK_AI_ACCEPTANCE.  
- stable_ready = false.  
- تشغيل كود يولده النموذج / Patch تطبيق تلقائي / Docker START / Docker CREATE عام = **غير مصرح به**.  
- لا تُحوّل حالة EMITTED_UNKNOWN أو RETURNED_CLAIM إلى SETTLED ولا تُدار Generation غير محسومة اعتمادًا على لقطة مخزون.  
- لا تساوي عبارة PASS إثبات Effective AI أو Independent L3.

**الدليل السابق المستعمل كخلفية، لا كدليل قبول للمسار الكامل:** [F5B1F تشغيل Root #42202611269](https://github.com/lijust/EREI-3.2/actions/runs/42202611269) = CREATE/INSPECT/DELETE ثابت دون START على Docker ثانوي؛ [F5B1J تشغيل Root #42300277663](https://github.com/lijust/EREI-3.2/actions/runs/42300277663) = فصل UID وحماية محلية HMAC على Proxy **اصطناعي**؛ اختبارات F5B1J = 242 PASS. **لا يوجد إثبات متكامل يربط التجربتين في Pipeline واحد**.

## 2. قاموس إلزامي للتقدم والإغلاق

| الرمز | المعنى الدقيق | هل يسمح بالانتقال/التشغيل؟ |
|---|---|---|
| NOT_STARTED | لم يبدأ العمل ولم يُثبت أي Gate | لا |
| ACTIVE | العمل ضمن نطاق مجمد، الأدلة غير مكتملة | لا |
| BLOCKED | يوجد نقص دليل أو مانع تشغيل | لا |
| GATE_PASS | اجتاز Gate محدد بمصدر ونتيجة فعلية | فقط إلى Gate التالي وفق الاعتمادات |
| CLOSED_PASS | جميع Gates المحددة للحزمة PASS، وقّع المسؤول وقُيّدت المخاطر | حسب **حدود الحزمة فقط** |
| CLOSED_NO_GO | اكتمل قرار التقييم بالرفض؛ لا توجد صلاحية تشغيل | **لا** |
| CLOSED_BLOCKED | انتهت ميزانية الحزمة والدليل غير كافٍ | **لا** |
| SCOPE_CHANGE_REQUIRED | مطلوب توسيع نطاق أو دورة إصلاح ثالثة | **لا** لحين إذن صريح |

لا توجد حالة **PARTIAL_PASS** تعادل CLOSED_PASS. نجاح الاختبارات التلقائية وحده لا يغلق اختبارًا يدويًا. عند غياب Run/Logs أو صدور PASS من Mock بدل Docker حقيقي: Gate = BLOCKED أو FAIL، لا PASS.

## 3. كارت الأدلة الإلزامي لكل Gate

لا يمكن تسجيل GATE_PASS إلا إذا توفرت **كل** الخانات التالية في تعليق GitHub أو ملف دليل محدد داخل المستودعَين:

| الخانة | شرط القبول الصارم |
|---|---|
| gate_id / contract_version | معرف واحد من G0–G3 وA0–A3 وB0–B3 وC0–C3، وv1.0 |
| status + decision_authority | قرار صريح مع شخص/جهة اعتماد؛ لا تكفي رسالة AI أو نجاح Workflow |
| reviewed_source | Commit SHA 40 حرفًا + مصدر/فرع GitHub ومسارات التغييرات |
| execution_witness | رابط Workflow Run ورقم Job ونتيجته، وملخص أسطر Log المعنية |
| positive_witness | مخرجات فعلية مطابقة لمعايير Gate، لا أرقام اختبار وحدها |
| negative_witness | أدلة منع السلوك الخطِر (رفض UID/START/CREATE/تسريب صلاحية...) |
| boundary/limitations | ما **لم** يثبت (Docker حقيقي أم Mock، Root أم Nonroot، أثر Host) |
| cleanup + rollback | حالة الموارد بعد الاختبار، وخطوة الرجوع لو فشل |
| issues/risks | الثغرات والاعتمادات المؤجلة وسبب عدم السماح بالتوسع |
| owner_signoff | اعتماد واضح في Issue الحزمة بعد مراجعة الأدلة؛ لا يُستنتج من dispatch |

إذا تعذر جمع أي خانة، النتيجة **BLOCKED**. من يراجع PR لا يجوز له ترقية ادعاء «local scoped» إلى «global protected».

## 4. Gate G — تثبيت الإطار ومنع العمل المفتوح (Issue #307)

| Gate | شروط الإغلاق |
|---|---|
| **G0 — Scope Freeze** | وجود هذه السياسة، Manifest بإصداره وبصمة المصدر في المستودعَين، وثلاث حزم A/B/C فقط؛ لا إعادة فتح أسماء مراحل F5B1 تلقائيًا |
| **G1 — Evidence Baseline** | ربط Run #42202611269 و#42300277663 و242 اختبارًا بسقف الإثبات الصحيح؛ قائمة النواقص والتعارضات موثقة |
| **G2 — Budget & Change Control** | حزمة واحدة ACTIVE؛ حد أقصى **دورتا إصلاح لسبب جذري لكل حزمة**، ولا يُحسب إعادة تشغيل CI بلا تعديل كدورة. توسيع ثالث = SCOPE_CHANGE_REQUIRED مع إذن من المالك |
| **G3 — Execution Authorization** | مراجعة المالك الصريحة للعقد وتثبيت الحالة «G_CLOSED_PASS» قبل إعلان أن A دخلت التنفيذ |

**لا يُغلق G تلقائيًا بمجرد إنشاء PR.** وجود الوثائق والاختبارات يجعل G0–G2 قابلة للمراجعة، أما G3 فقرار بشري.

## 5. الحزمة A — Real Docker Read-Only Verifier (Issue #308؛ تعادل F5B1K)

**الهدف الوحيد:** قراءة Docker Daemon ثانوي حقيقي من Verifier ذي صلاحيات منفصلة عبر Proxy **GET-only**، دون إنشاء أو تشغيل حاوية في حزمة A. منع CREATE/START/DELETE لدى المراقب مطلق. أي فشل في قراءة Docker الحقيقي لا يمكن استبداله بنتائج Mock السابقة.

| Gate | شرط PASS | دليل الرفض |
|---|---|---|
| **A0 — Contract & Threat Model** | مصدر Docker ومساره خاصان بالاختبار؛ تحديد daemon PID/boot ID/socket/epoch وGET allowlist ونطاق CID وخطة cleanup، ومراجعة Root source pin والتبعيات | مسار Host Docker غير معروف / فتح endpoint عام / عدم حسم المسؤولية |
| **A1 — Nonroot Negatives** | اختبارات فعلية لرفض Controller المباشر، UID/PID خاطئ، Socket غير مصرح، POST/DELETE/START، CID مخالف وEpoch قديم؛ كلها PASS في CI بلا sudo | نجاح أي طلب تعديل أو سقوط اختبار سلبي |
| **A2 — Owner-Manual Real Docker Read** | Workflow Dispatch منفصل من المالك؛ real rootful **disposable secondary dockerd**؛ تحقق OS peer؛ GET حقيقي بقائمة صغيرة ثابتة؛ Default Host Docker قبل/بعد مطابق، لا START/CREATE، 0 موارد خاصة متبقية | Job مع SKIPPED، Mock فقط، أو أي تعديل على Host Docker |
| **A3 — Closed Evidence Packet** | جمع SHA/Run/Job/logs وأدلة الرفض وcleanup وقراءة Docker الحقيقية ومراجعة المالك؛ إعلان **A_SCOPED_READ_ONLY_PASS** فقط | غياب تقرير من أي Gate أو ادعاء Independent Settlement |

**الحسم:** A = CLOSED_PASS عند A0+A1+A2+A3 كلها PASS؛ خلاف ذلك CLOSED_NO_GO/CLOSED_BLOCKED بعد نافذة الإصلاح. حتى PASS لا يعني Terminal Settlement أو Quiescence. لا تُنفَّذ B/C تشغيليًا إن A = NO_GO، ويمكن فقط أرشفة الوضع وإصدار PILOT_NO_GO.

## 6. الحزمة B — Integration & Consolidation (Issue #309)

**الهدف:** نقطة دخول واحدة للـPilot **الاستشاري الذي لا ينفذ الكود**، وإزالة ازدواج التجارب ذات الصلة دون تغيير واجهات أمان Stable.

| Gate | شرط PASS | دليل الرفض |
|---|---|---|
| **B0 — Real Call-Path Inventory** | حصر نقطة دخول Pilot وكل مسارات J4/J4S/CLI/Jobs/Socket/FD التي يمكن الوصول إليها منها في المستودع، وتصنيف Allowlisted / Denied / Unknown؛ تسجيل SHA لكل ملف | أي مسار قابل للوصول من Pilot مجهول وغير معزول |
| **B1 — One Non-executing Route** | بوابة واحدة ترفض Docker START وCREATE العام وHost Docker وتنفيذ Model/Patch؛ اختبارات مسار مسموح ورفض تجاوز فعلي | إمكان وصول Pilot لمسار كود غير موثوق أو Docker مباشر |
| **B2 — Consolidated Source & Regression** | Reconcile للـPRs والمكونات، تقليل التكرار حيث لا يغير السلوك، Source pins صحيحة، الاختبارات المعمول بها PASS وRollback موثق | استبدال سجلات أصلية أو بناء مكوّن أمني ضخم جديد |
| **B3 — Review & Signoff** | جدول قديم/جديد شامل مسارات Pilot ونتائج CI وNegative وقيود النظام؛ اعتماد المالك **B_PILOT_ROUTE_CONSOLIDATED** | أي ادعاء Global Docker Exclusivity دون إثبات |

**لا يلزم إثبات الحصرية العالمية لمسارات Docker غير المتصلة بالـPilot** لإغلاق B، لكن يجب إثبات **عدم إمكانية الوصول إليها من مدخل Pilot**. وجود مسار Pilot مجهول قابل للتنفيذ = NO_GO.

## 7. الحزمة C — Engineering Pilot Decision (Issue #310)

**الهدف:** غلق قرار جاهزية Pilot استشاري محدود. لا تُخلط جاهزية البنية الهندسية مع جودة النموذج/الاعتماد الأمني.

| Gate | شرط PASS | دليل الرفض |
|---|---|---|
| **C0 — Preregister** | قبل التنفيذ تثبيت Source SHA، السيناريوهات الثلاثة، المدخلات وOracle وProvider وحدود الاستهلاك ومقاييس القبول/الرفض وعدم تغييرها بعد مشاهدة النتائج | تعديل المعيار أو اختيار الحالات بعد ظهور النتائج |
| **C1 — Three E2E Observations** | **3 سيناريوهات ثابتة** مع Evidence فردي: (1) تقرير/اقتراح Advisory-only دون تطبيق، (2) فشل Provider/Network يرفض بأمان، (3) مدخل عدائي يحاول فتح تنفيذ كود/Docker ويُرفض. لا Write ولا CREATE/START ولا اعتماد آلي | فشل حالة أمنية واحدة، أو عدم وجود Evidence مباشر |
| **C2 — Independent Decision Review** | مراجعة بشرية للسجلات الثلاثة ونتائج A/B، صفر إخفاق في بوابات السلامة، شرح المجهولات وRollback؛ اعتماد المالك للقرار النهائي | نتيجة معتمدة من AI نفسه أو مستندة إلى عدد اختبارات فقط |
| **C3 — Model Effectiveness Separation** | بروتوكول مستقل **مُسجّل مسبقًا** لقياس المنفعة بحالات عمياء ومعيار مصدر خارجي؛ يُكتب أن Effectiveness = NOT_ESTABLISHED لحين ظهور الدليل | الادعاء أن 242+ اختبار أمان = تحسن جودة AI |

**القرار النهائي محدد بثلاث نتائج فقط:**
- **PILOT_ADVISORY_ONLY_GO:** A/B/C = CLOSED_PASS كلها، وقيود Advisory-only مثبتة في الكود؛ لا يساوي Stable أو Independent AI Acceptance.
- **PILOT_NO_GO:** إخفاق محدد في متطلب ضروري؛ يُغلق التقييم مع سبب ودليل وبلا تشغيل.
- **PILOT_BLOCKED:** دليل ناقص أو مانع خارجي لم يُحل ضمن الميزانية؛ يُغلق التقييم معلّقًا، ويحتاج فتحًا معتمدًا لتغييره.

إن كان A أو B قد أغلق NO_GO/BLOCKED، لا تستمر تجارب C التشغيلية لمجرد استكمال جدول.

## 8. سياسة التوقف والميزانية (Hard Stop)

- **الحزم بالضبط 3، Gate IDs لا تتغير في النسخة v1.0.** لا نعد بفترة زمنية أو نسبة إنجاز قبل اكتمال بيانات التنفيذ.
- **حزمة ACTIVE واحدة فقط.** لا يبدأ تنفيذ B قبل إغلاق A، ولا C قبل إغلاق B، باستثناء التحضير الكتابي الذي لا يغير الكود أو الادعاءات.
- **دورتا إصلاح كحد أقصى لكل حزمة** بعد ظهور مشكلتين جذريتين؛ إعادة تشغيل اختبار دون تعديل ليست دورة. بعد حد الإصلاح: CLOSE_NO_GO أو CLOSE_BLOCKED؛ لا دورة ثالثة من دون Change Request موقّع.
- Change Request يحدد **الخطر الجديد، سبب عدم إمكانية تأجيله، الفرق عن v1.0، Gate المتأثر، معايير الإغلاق، التكلفة/الجهد، مَن سيعتمد**؛ ولا يُدمج في المهمة الحالية تلقائيًا.
- إذا ظهرت ثغرة حرجة تسمح بتجاوز عزل Pilot: توقف فوري + BLOCK، ثم قرار منفصل؛ لا نكمل تشغيلًا بداعي الالتزام بموعد.
- لا يتم تحويل مسار Stable إلى شرط إغلاق متحرك للحزمة؛ ولا يتم تجاوز شرط **ضروري لسلامة Pilot المحدود** بحجة تأجيل Stable.

## 9. المسار المستقل المؤجل — STABLE-DEFERRED (Issue #311)

**خارج الحزم الثلاث:** إثبات Terminal Settlement بمراقب مستقل عن Root/مفتاح خارجي، دفتر أدلة مستقل ومتين بعد الانقطاع، مانع سببي للـLate CREATE، حصرية جميع مسارات Docker والتحقق من FDs، الترحيل الكامل للتنفيذ الآمن عبر J4/J4S، تقييم أمني L3 مستقل، وإثبات جودة النموذج في مهام واقعية.

**معيار فتحه لاحقًا:** موافقة جديدة من المالك + Threat Model مستقل + Budget وStop Rules + مسار أدلة مستقل. لا يبدأ بسبب PASS في A ولا يُفسَّر CLOSED_PASS في C على أنه اعتماده.
