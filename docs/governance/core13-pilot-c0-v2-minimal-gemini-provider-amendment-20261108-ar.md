# EREI Core13 — C0 v2: الحد الأدنى للاتصال الاستشاري بـGemini

**8 نوفمبر 2026 | تغيير محدد داخل C0 قبل أي C1 | التوثيق والاختبارات فقط؛ لا اتصال فعلي بالنموذج.**

## 1. لماذا احتجنا التعديل؟

بعد إغلاق الحزمتين A وB بتوقيع المالك (12/16 بوابة)، كشفت نسخة `C0 v1` أن `B1` مجرد CLI حتمي لقراءة 14 مسارًا ذا بصمة مصدر، ولا يستورد شبكة أو نموذجًا؛ وبالتالي لا يستطيع اختبار `C1-02` إثبات فشل اتصال بمزود فعلي. لذلك ظل `C1-02=BLOCKED_NO_PROVIDER_SEAM`. **استمرارنا في C1 دون معالجة ذلك كان سيخلق نتيجة مزيفة.**

وافق المستخدم صراحة في المحادثة على توصية **إعادة استخدام طبقة الاتصال القديمة بصورة محدودة**. لا تُفسر هذه الموافقة باعتبارها تصريحًا بالاتصال الفعلي أو دفع تكلفة أو كشف ملفات خاصة. يلزم اعتماد المالك النهائي على GitHub قبل أي C1.

## 2. ما الذي بُني فعلًا؟

**كود جديد واحد** في مستودع التطبيق الخاص فقط:

`tools/core13_pilot_c0_gemini_readonly_boundary.py`

- يعيد استخدام **منطق محدود** من مصدر التطبيق السابق `tools/core13_gemini_pair_live.py` في فرع `core13/optin-gemini-paired-model-runner-20261028`، Git blob `df6b8ca9e64882f43abb7ac43b68085bb8315fb0`.
- **لا يستورد** مُشغل التجربة الثنائية، ولا كتابة الأدلة أو دفتر التشغيل أو رفع ملفات مصدرية خاصة؛ لا يعتمد على Docker أو Root أو Subprocess أو مصحح برمجي أو `B1` Runtime.
- يملك دالة واحدة `provider_attempt(api_key=..., opener=...)` بدون CLI أو اتصال عند الاستيراد. المفتاح يمر في ذاكرة Future Owner-runner بعد الموافقة فقط؛ لا يُطبع أو يوضع في الرابط أو يُخزن في GitHub أو يقرأ من Environment داخل هذا المكوّن.
- يثبت `gemini-3.5-flash-lite` (نموذج Gemini رسمي مستقر وفق urlالمواصفات الرسميةhttps://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) على endpoint واحد `https://generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash-lite:generateContent`، وهو **POST لإنشاء نص إرشادي فقط**، وليس HTTP GET. لا يسمح بإرسال أمر تنفيذي أو أدوات Function Calling/Code Execution.
- يستخدم Prompt ثابتًا **افتراضيًا وغير سري** دون أسماء المستودعات أو معرفات وحدات أو نصوص الشيفرة الخاصة.
- Request واحدة كحد لكل استدعاء، بلا Retry، Timeout=10 ثوانٍ، Response<=8192 bytes، MaxOutputTokens=128، ورفض Redirect وProxies البيئية. لا يوجد تشغيل تلقائي عند Push أو PR.
- يفحص مخطط JSON ويقبل فقط `policy=DENIED` وسببًا نصيًا محدودًا، ويعيد `model_result_independently_accepted=false`. مخرجات النموذج **نص استشاري لا يُنفذ ولا يُطبق**.
- يفصل `C0_PROVIDER_UNAVAILABLE_5XX_STOP` عند HTTP 502/503/504 و`C0_PROVIDER_NETWORK_UNAVAILABLE_STOP` عند انهيار الشبكة عن `C0_PROVIDER_HTTP_DENIED_STOP` مثل HTTP 401. خطأ المصادقة **ليس** دليلًا على انقطاع مزود.

**لم نغير كود B1** (Git blob ثابت `8be64b9a1a492e78b97903d95c44fcdea77099ce`)؛ وظيفته الحالية محمية من دخول هذه الطبقة. **لم ننشئ نقطة دخول تنفيذ ثانية**.

## 3. عقد C0 v2 دون المساس بالإصدار الأصلي

حفظنا `contracts/core13-pilot-c0-prereg-three-probes-v1.json` ببايتاته السابقة ودليل النقص الأصلي، وأضفنا:

`contracts/core13-pilot-c0-prereg-three-probes-v2.json`

يحتفظ **بثلاثة سيناريوهات فقط** وبمنع التغيير اللاحق للـOracle:

| Case | مصدر/دخل C1 المسبق | Oracle المسبق |
|---|---|---|
| C1-01 | B1 `inspect_route` لمسار J4 المعروف؛ تقرير حتمي فقط | `exit=0`، `policy=DENIED`، Counter للعمليات الجانبية = صفر |
| C1-02 | دالة Gemini المثبتة، **اتصال HTTPS حقيقي بإذن المالك** إذا توافرت بيانات الاعتماد وظروف الاختبار | نجاح الفشل الآمن فقط إذا ثبت **فشل شبكة حقيقي أو HTTP 502/503/504**، بلا نص استشاري أو Retry أو تسرب أسرار. HTTP 401 أو Mocked URLError أو استجابة ناجحة **لا تُحتسب فشل مزود** |
| C1-03 | JSON عدائي يحاول `execute` وDocker وCode من خلال B1 | `exit=2` و`DEFAULT_DENY` وصفر تنفيذ أو ملفات معدلة |

**أهم قيد:** أضفنا مصدر اتصال صالحًا للاستدعاء، لكن **لم نشهد عطل شبكة حقيقيًا**؛ لا يجوز اختلاق عطل في CI أو تسميته Live Provider Outage. لذلك حالة C1-02: `BOUNDARY_IMPLEMENTED_REAL_FAULT_NOT_YET_OBSERVED`؛ وC1 ما زالت `NOT_STARTED`.

## 4. الحدود المالية والعملية

- نموذج واحد ثابت، واستدعاء واحد **كحد لكل نداء للدالة**، دون إعادة محاولة، وToken output limit=128. الحد الإجمالي للتجربة المستقبلية يعتمد على Runner ومراجعة المالك؛ لم ننفذه بعد.
- **لا ندّعي تكلفة دولار مؤكدة**؛ `provider_api_cost_usd_max=null` حتى يتحقق المالك من حدود الخطة والتكلفة ويأذن باستدعاء حقيقي.
- فحوص CI تشتغل Offline، تستخدم `opener` مصطنعًا لا يعود إلى Google، وتختبر Request shape، غلق HTTP 401/429/503/302 وأخطاء الشبكة ورفض أدوات/مخرجات غير صالحة؛ **ليست أدلة C1 مستقلة**.
- أي عطل في شبكة/مصادقة/Quota يوقف العملية؛ 429 **No Retry** كما في المصدر السابق. لا تنسخ مفاتيح DPAPI إلى GitHub.
- `AI_ACCEPTANCE=BLOCK_AI_ACCEPTANCE` و`stable_ready=false`، ولا يوجد دليل على منفعة نموذج AI في مشروع EREI حتى الآن.

## 5. شرط استكمال C1

1. مراجعة المالك **لعقد C0 v2 والكود والاختبارات** في [Issue #310](https://github.com/lijust/EREI-3.2/issues/310) وتوقيع تصريح C0 محدد، لا يفعّل C1 تلقائيًا.
2. اختيار طريقة Owner-local للحصول على مفتاح Gemini من DPAPI الموجود سابقًا **دون إرساله إلى GitHub**، وتوثيق Cost/Tier opt-in، والحفاظ على Source SHA وبيئة التنفيذ.
3. مراجعة خطة إحداث/التقاط **انقطاع شبكة حقيقي وغير مدمر** عند Endpoint المثبت أو قبول نتيجة `BLOCKED` إذا لم تظهر استجابة فشل حقيقية؛ لا تستخدم Mock لتزوير شرط C1-02.
4. تشغيل **الثلاث حالات فقط** في موافقة C1 لاحقة وحفظ أدلة مستقلة لكل واحدة. لا تتغير الحدود بعد ظهور النتائج.
